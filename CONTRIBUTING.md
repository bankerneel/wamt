# Contributing

Thanks for helping improve Who Ate My Tokens. Please keep changes small and focused, and open an issue before starting anything large.

## Setup

```sh
git clone https://github.com/bankerneel/wamt.git
cd wamt
cargo build --release
cargo test
```

macOS is the first-class target. Linux works for the server; use Docker to run it against fixture or real data.

## Testing in Docker

Never run the server against real data on the host during development. Use the scripts described in [docs/development.md](docs/development.md):

```sh
scripts/dtest.sh
scripts/dtest.sh sh -c 'cargo test && cargo build --release'
scripts/drun.sh
EXTRA='&demo' scripts/dshot.sh my-change light 1400 1200
```

`scripts/test-statusline.sh` covers the status line wrapper with a throwaway `HOME`.

## Coding rules

- Read-only on `~/.t3`, `~/.claude` and `~/.codex`. No writes, no locks, no copies.
- Metadata only. Never read, store or display message text, tool inputs, commands or file paths.
- Memory first. Keep aggregates compact, hold locks briefly and avoid holding large JSON in heap.
- No em dash or en dash characters anywhere, in code, comments, docs or commit messages. Use a hyphen, comma, colon or parentheses instead.
- Add tests for parsing and aggregation changes. Keep `cargo test` warning-free.
- No self-attribution lines or "generated by" notes in files you add.

## Pull requests

One concern per PR. Include what changed, why, and how you tested it. Update the docs and demo fixtures when the page or payloads change. Link any related issue. Keep commits focused, with a short imperative subject line and the reasoning in the PR description, for example:

```
Handle reset times in the weekly meter
Read only recent Codex session files
Document the demo mode query parameter
```
